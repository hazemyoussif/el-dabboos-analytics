# ADR 032: Source-neutral published analytics capabilities

Status: Accepted (2026-10-06).

The domain owns `PublishedAnalyticsCapabilities`: tenant-scoped releases with dataset, source, mapping ID/version, certification reference, certified period, explicit summary metrics, exact metric/dimension pairs and analysis permissions. A release list leaves room for approved multi-source composition; execution still uses the existing explicit serving binding and implements no cross-source joins. Physical recipes remain exclusively in source mappings/adapters. Canonical semantics and tenant presentation preferences remain distinct from those recipes. No universal revenue alias or new tenant metric-policy subsystem is introduced.

PostgreSQL projects the approved immutable mapping through its approval-linked exact, complete reconciliation coverage. Migration 010 exposes a tenant-checked, read-only coverage summary without granting runtime access to raw case specifications or group keys. Both existing business certification and technical certification are required. Mapping declarations alone never authorize consumer capabilities. The initial projection includes additive outputs with exact controls; input controls do not independently approve ratios, distinct counts, snapshots, time breakdowns or analyses. Reconciliation for one dimension never implies another pair. Enforced policy dimensions must also be covered. Synthetic composition explicitly retains catalog capabilities; a missing PostgreSQL serving binding returns an empty certified projection, never synthetic fallback.

HTTP query, template instantiation, dashboard execution, generated/edited output and saved-record execution check fresh published capabilities before execution. Existing repository certification and tenant/policy guards remain in place, including `Uncertified metric/dimension combination`. Per-series execution metadata records source-neutral release provenance. Saved records retain the existing explicit Save/version lifecycle; this change does not pin historical records to releases or silently create saved dashboards. Immutable old definitions, approval references and facts remain preserved when a new release is explicitly certified and bound.

Template requirements derive from their canonical widget series, including grouping, analyses and semantic class. Compatibility is supported, partially supported or unsupported; user authorization is a separate restriction. Automatic selection chooses a fully supported authorized template. The generic Sales Performance remains unchanged and preflights before execution. The source-neutral Sales & Invoicing template requests four explicit canonical KPI metrics and uses the certified period and tenant labels. Synthetic tenants keep Sales Performance as their initial template.

Planner context and schema contain only authorized published metrics, narrowed dimensions and analysis/period capabilities. Deterministic generation compilation owns the omitted-period default. Canonical validation, authorization and fresh post-output published checks remain mandatory. Manual palettes hide unavailable executable metrics, restrict grouping choices and preflight every analysis/application; blank drafts start in the certified period. Server checks prevent forged client bypasses. Global theme preferences remain outside dashboard content.

Limits: certified analysis permissions are currently conservative and empty; approval of new semantics/pairs/periods requires new evidence and the existing governed lifecycle. Multi-release query routing, historical saved-record pinning, cost semantics, receivable snapshots, prior-year backfill and sync remain future work.
