# ADR-024: Compact model intent and deterministic dashboard generation

Status: Accepted (October 2026)

Context: A configured endpoint accepts minimal structured JSON and references but rejects the full projected canonical DashboardSpec schema. Canonical correctness and model communication have different constraints. Removing domain validation or adding vendor-specific schema workarounds would weaken the boundary.

Decision: Application owns a transient, shallow DashboardGenerationPlan: bilingual titles, bounded widgets/series, optional date preset/range/business filters and flattened explicit analysis intent and optional sparse requestedPresentation. The model omits unrequested type, color/style and analyses. Widget root type/style properties are rejected. Provider generation requests use its portable projection under `dashboard_generation_plan`, with authorized metric choices. AJV plus deterministic date/title/top-N pairing checks validate the plan. A pure visualization resolver chooses KPI without grouping, compatible time Line, compatible categorical Bar, and mixed-unit Table, retaining explicit types under existing canonical policy. It owns orientation/legend/curve/pie/combo defaults; type-incompatible presentation fields fail plan schema validation rather than disappearing; deeper incompatibilities still fail canonical semantic validation. A pure compiler creates stable IDs, canonical analysis/presentation, tenant-timezone periods and domain default 12-column layout. Full canonical spec validation and post-planner authorization run before execution. Plans are never persisted. No SQL, React, arbitrary expression language, policy filters or chart-library properties are allowed.

Initially editing retained projected canonical DashboardPatch v2. [ADR-025](025-compact-dashboard-edit-plan.md) now uses transient sparse edit intent compiled into canonical patch, preserving patch/application/resulting-spec validation and authorization. Repair limits remain 0–2, and transport errors bypass repair. Optional diagnostics belong to the API root; application code never reads environment variables.

Consequences: Provider contract complexity can remain bounded independently of persistence/domain schemas. Fake HTTP and deterministic compiler tests run without an endpoint or key. Live generation quality/compatibility remains a separate manual endpoint gate. The separately approved edit-plan compiler and live edit evidence are recorded in ADR-025. The web presents real operation state and elapsed time, with no invented internal stages; failures leave the draft unchanged.

Governed palette names (`default`, `blue`, `green`, `orange`, `purple`, `red`, `neutral`) extend WidgetPresentation and canonical spec/patch presentation schemas without changing version or weakening any existing constraint. Only the web centralized theme resolves actual accessible Light/Dark colors. Manual palette edits use normal widget replacement; sparse AI palette intent compiles through DashboardEditPlan (ADR-025) to the same canonical patch.

Generic API inference controls send temperature (default 0) and max_tokens (2048), with thinking_budget_tokens and seed only when configured. Strict json_schema is retained; reasoning_content is ignored. HTTP 429 is a distinct safe rate-limit failure, never a semantic repair. Provider diagnostics support bounded object/array error envelopes without raw text. Model deployment guidance belongs in provider documentation, never application conditionals.

Top-N follow-up: GenerationSeries excludes per-series mark entirely. Explicit Combo generation assigns first Bar/rest Line in code; canonical series marks and canonical AI edit remain unchanged. Prompt guidance explicitly maps top/bottom N to direction/limit on the first selection series and includes one compact Top-5 horizontal blue Bar example. Presentation compatibility and omission rules prevent requested styles from becoming invented defaults. Existing domain visualization reasons enrich bounded generation repair/terminal diagnostics only after canonical rejection, retaining generic public errors and unchanged validators.

Type-specific presentation follow-up: requestedPresentation is omitted entirely without explicit presentation intent. When present it requires type. Within the summary/grouped union, summary permits KPI and five disjoint grouped presentation branches cover the other seven types: Bar allows palette/orientation/legend; Line/Area/Combo palette/curve/legend; Pie palette/pieVariant/dataLabels/legend; Treemap palette/dataLabels/legend; Table palette only. The separate summary branch allows KPI palette only. Every branch forbids additional properties. Disjoint type enums avoid const or discriminator extensions; identical option sets share branches, and palette/dimension enums use existing portable $defs/$ref support. String enums need no redundant type keyword. Provider projection preserves these restrictions. Canonical validation remains authoritative for units, grouping, analysis and other deeper compatibility. Resolver defaults and code-owned Combo marks remain unchanged. Live endpoint acceptance remains a separate verification gate.

## Structural summary/grouped follow-up

Summary generation widgets forbid dimension, require exactly one series and allow only optional explicit KPI presentation (palette only). Grouped widgets require dimension and 1–8 series; their optional type-specific presentation excludes KPI. Two closed, disjoint oneOf branches enforce this in the original and projected schemas; TypeScript mirrors the categories. Dimensionless Line/Bar/Area/Pie/Treemap/Combo/Table and grouped KPI cannot be represented. Deeper metric/dimension, unit, analysis, composition, Combo count and Top-N anchor rules remain canonical. Defaults remain code-owned: implicit summary KPI, compatible time Line, compatible category Bar, mixed units Table. No model/provider conditional or new schema keyword was introduced.

The current unrestricted projected generation schema is 3,534 serialized bytes with reference-expanded depth 13, versus projected DashboardSpec at 3,458 bytes/depth 14. This is a modest increase from the prior 3,088 bytes/depth 11 to prevent impossible grouping states; it is 2.2% larger than canonical in bytes and one level shallower. Tests bound size to at most 105% of canonical and depth to at least one fewer level, alongside infrastructure exclusion. Actual requests restrict the shared metric enum to authorized capabilities. Compact model output and code-owned infrastructure remain the purpose; this revision does not claim a serialized size saving.

## Multi-widget presentation adherence

Explicit governed presentation intent remains model-owned. The generation instruction treats requested type/orientation/palette/options as required, attaches each only to its corresponding widget in a multi-widget request, and asks the model to check for dropped presentation adjectives before returning JSON. The existing horizontal-blue Top-5 example remains the single compact example. The deterministic compiler preserves emitted intent but never parses the raw request or reconstructs an omitted palette. Valid output that omits Blue still has no Blue token; prompt adherence is a live model acceptance concern, not hidden inference.
