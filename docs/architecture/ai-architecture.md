# AI architecture

`LLMProvider.generateStructured` accepts messages and a named strict JSON Schema response format. Its output has type `unknown`; a future caller must apply DashboardSpec/Patch v2 schema and semantic validation. `DashboardPlanner` remains the domain-facing generation/editing port and receives the server-governed TenantProfile for market and dialect context. It may select or adapt a market-neutral template, or compose a new dashboard from available metrics. It never asks a provider to calculate metrics or emit code, SQL, or chart-library configuration.

The deterministic MockDashboardPlanner proves the English/Arabic prompt and edit workflow, including a few Iraqi/Egyptian phrases. It is not a full dialect parser. `planningEvaluationCases` are provider-neutral expectations for English, Modern Standard Arabic, Iraqi Arabic, Egyptian Arabic, mixed English/Arabic, Arabic-Indic digits, and Western digits. They include template reuse/modification, new composition, clarification, planned-metric rejection, and multi-metric chart/table requests. These cases are not claims of mock-planner coverage.

Manual templates and the renderer work when planning is disabled. Future Muse, llama.cpp, or other provider adapters must share contract validation and evaluations. Provider-specific cost, token, and GPU telemetry is optional. Real model accuracy, latency, and pricing have not been measured.
