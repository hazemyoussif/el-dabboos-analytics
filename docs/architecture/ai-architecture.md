# AI architecture

`DashboardPlanner` remains the domain-facing generation/editing port. `StructuredDashboardPlanner` is the provider-backed implementation; `MockDashboardPlanner` remains the default demo fallback. The structured planner receives server-authorized `PlannerCapabilities`, a controlled tenant/market profile, available semantic metadata, compatible template metadata, and the active DashboardSpec/Patch v2 schemas. It sends the user prompt (or current spec and edit instruction) through `LLMProvider.generateStructured`; the provider never receives repository access, source mappings, SQL, React, or chart-library configuration.

The OpenAI-compatible HTTP adapter implements the provider-neutral `LLMProvider` port with a named strict JSON Schema response format. Its returned output remains `unknown`. The planner applies the existing JSON Schema and semantic validation, checks metric authorization, and, for edits, applies the patch to the current spec and validates the result before returning it. A bounded repair loop requests corrected JSON for malformed or invalid output. Transport failures are separate from invalid model output. API routes remain provider-independent and use the same validation/authorization/execution path.

The deterministic mock planner proves a bounded English/Arabic prompt and edit workflow, including a few Iraqi/Egyptian phrases. It is not a full dialect parser. `planningEvaluationCases` are provider-neutral expectations for English, Modern Standard Arabic, Iraqi Arabic, Egyptian Arabic, mixed language and numeral styles, template reuse, new composition, clarification, planned-metric rejection, and multi-metric requests. They are not claims of model or mock coverage.

Manual templates and the renderer work when planning is disabled. The local llama.cpp setup and exact environment variables are in [local llama planner](local-llama-planner.md). CI uses fake HTTP responses; real Bonsai 2 accuracy, latency, and schema adherence have not been measured. Muse, hosted model adapters, and provider-specific telemetry remain outside this implementation.
