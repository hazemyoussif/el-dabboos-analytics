# Architecture overview

The deterministic vertical slice has four layers. `packages/domain` defines canonical metrics, aggregation recipes, bounded analysis contracts, and versioned dashboard schemas. `packages/data` contains the canonical-measure engine and mock/SQLite repository adapters. `packages/application` turns each validated widget into an AnalyticsQuery and executes it, isolating failures per widget. `apps/api` exposes this workflow over Fastify, and `apps/web` renders the returned specification and results in English or Arabic. Dependency direction is `web → API → application → domain/repository port`; the SQLite implementation remains behind the port.

The demo planner is deliberately rule-based. It recognizes a small documented set of English and Arabic sales requests and edits, emits a DashboardSpec or DashboardPatch, and goes through the same validation and execution path as a manually selected spec. Its unsupported-intent error is visible to the user. The provider-neutral LLMProvider structured-output port remains unimplemented; no prompt can generate SQL or code.

Additive measures sum by default. Ratios and durations divide aggregated components; sales growth derives from a revenue comparison; balances select the latest observation per entity as of the period end. Derived metrics are never persisted as independent facts. Analysis is a bounded pipeline, with UTC calendar alignment for month/quarter/year comparisons and leap-year/month-end clamping.

The local API permits only the explicit fake tenant `demo` using `x-tenant-id`. This is a demo gate, not production authentication. The browser sends it automatically. API validation and the repository enforce tenant context; the SQLite adapter filters all fact reads by tenant. Each AnalyticsResult carries source ID, execution time, optional source-as-of time, and metric type/unit metadata. The API server defaults to the repository-root `demo.db`, so seed, dev, and built-start commands use the same local database.
